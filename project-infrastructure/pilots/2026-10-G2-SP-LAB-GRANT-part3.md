## F-25 (P1). Новый агент переспрашивает решённое

**Что произошло.** Ответы и решения пользователя записывались в журнал задачи («2026-10-06: ответы пользователя: Kapton новый, ЭВТИ есть…»). Отдельного списка «это уже решено» не было. Новый агент его не находил и спрашивал заново — пользователь назвал это главной проблемой.

**Недостаток стандарта.** COMMON §4 запрещает дневник в `STATE.md`, §11 называет `TASKS.md` рабочим набором, но не говорит, **как** держать текущие решения по задаче и **что делать до вопроса пользователю**.

**Решение в пилоте (проверено).** У активной задачи в `TASKS.md` — два раздела-сводки:
- «Решено» — текущие решения и ответы пользователя (отменённое удаляется, новое вносится сразу, в той же сессии);
- «Открыто» — что не решено.
Правило: **прежде чем спросить пользователя — проверь «Решено»** (при необходимости — журнал задачи).

**Предложение.** COMMON §11 `TASKS.md` и runtime baseline `AGENTS.md`:
> An active task keeps two current summaries: **Decided** (current decisions and user answers; superseded items are removed, new ones added in the same session) and **Open** (unresolved questions). Before asking the user a question, check the task's Decided list (and, if needed, its journal); do not re-ask settled questions. A user answer or decision is recorded in Decided in the same session, even during a read-only/informational request.

## F-26 (P1). Нет короткой точки входа: «где мы сейчас»

**Что произошло.** `STATE.md` формально соответствовал COMMON §4/§11 (фаза, выводы, ближайшие действия), но разрастался датированными разделами: текущая работа была одним разделом из двадцати. Новый агент не понимал, с чего начать.

**Решение в пилоте (проверено).** В начале `STATE.md` — раздел «Сейчас — начни отсюда», ≤ ~15 строк: что активно, где мы, следующий шаг, где решения, ключевые файлы, что не активно. При изменении положения **переписывается**, а не дополняется. Устаревшие разделы STATE — дословно в `_ai/archive/state/`, в STATE — итог в несколько строк.

**Предложение.** COMMON §11 `STATE.md`, §3 Startup:
> `STATE.md` starts with a short **Now** block (≈15 lines max): active work streams, where things stand, the next step, where decisions/open questions live, key files. It is rewritten, not appended, whenever the situation changes. Startup reads the Now block first; other STATE sections only when relevant. Superseded STATE sections move to a scenario-defined archive (e.g. `_ai/archive/state/`), leaving a short summary.

## F-27 (P2). Где вести журнал длинной задачи (решение для F-22)

**Решение в пилоте.** Журнал задачи — `_ai/journal/T-###.md` (новые записи сверху, одна датированная запись на шаг: что сделано, числа, обоснования). В `TASKS.md` у задачи — статус, «Решено», «Открыто», ссылка на журнал. Журналы четырёх длинных задач по накопителю (T-011, T-014, T-017, T-018) вынесены так же, в `TASKS.md` осталась строка статуса.

**Предложение.** G2 support locations + COMMON §11 `TASKS.md`:
> Long-running tasks keep their working log in `_ai/journal/T-###.md` (newest first). `TASKS.md` holds only status, Decided, Open and a link to the journal; short tasks may omit a journal.

## F-28 (P1). Параллельные агенты, форки и дочерние сессии пишут в одну память

**Что произошло.** Пока основной чат обсуждал перестройку памяти, его форк продолжил закупку и записал в те же `STATE.md`/`TASKS.md` новые решения. Ничего не потерялось только потому, что оба агента забирали свежую версию перед записью. Риск — агент, который **переписывает сводку целиком по памяти** часовой давности.

**Недостаток.** COMMON §14 требует перечитать файл перед записью, но не говорит о сводках, которые «переписываются», и о форках/дочерних сессиях как о параллельных агентах.

**Решение в пилоте.** Правило точечной правки: (1) сразу перед правкой забрать свежую версию из GitHub; (2) менять только свои строки, сводки по памяти целиком не переписывать; (3) сразу commit + push; если push отклонён — забрать свежее, повторить правку, конфликт в строке решить вручную.

**Предложение.** COMMON §14:
> Forks and child sessions of the same chat are parallel agents: they share only the canonical stores, not each other's context. Rewritable summaries (Now, Decided, Open) are edited **surgically**: fetch the current file immediately before the edit, change only the lines your work affects, never regenerate a whole summary from remembered context, and push immediately.

## F-29 (P1). Временный клон стёрт системой — потеряны неотправленные коммиты (G2 Mode B)

**Что произошло.** Клон репозитория (Mode B) лежал во временной папке сессии. Плановая уборка `Temp` удалила часть файлов, включая три локальных коммита, которые ещё не были отправлены. Восстановлено по уцелевшим рабочим файлам.

**Предложение.** G2 Mode B:
> A Mode B checkout in a temporary workspace may be deleted by the OS or the harness at any time. Commit **and push** after every logical change; never keep unpushed commits across turns. If the checkout looks damaged (missing files, broken `.git`), re-clone and reconcile from surviving working files.

## F-30 (P2). `AGENTS.md` слишком велик, а главное — не в начале

**Что произошло.** Каждый агент читает `AGENTS.md` целиком. Порядок шаблона COMMON §11 — `Infrastructure` первым. В пилоте ~10 КБ занимали редкие случаи: полная транзакция, подробности проверки синхронизации, временная работа, artifact-only режим с шаблоном отчёта, режим облачного чата (локальное расширение D-002).

**Решение в пилоте.** Порядок: короткое вступление → «Запуск» → «Сводки, журналы и параллельная работа» → «Как работать с пользователем» → «Ведение документов» → «Правила работы» → «Перед завершением» → модель G2 и доступ → «Запись в artifact root (кратко)» → пропорциональный путь → «Особые режимы» → workspace → `Infrastructure` (внизу). Редкие разделы перенесены дословно в `_ai/infrastructure/ARTIFACT_ROOT.md` и `_ai/adapters/CLOUD_CHAT.md`, в `AGENTS.md` — отсылки по 1–3 строки. 29,7 → 22,3 КБ.

**Предложение.** COMMON §11 `AGENTS.md`, runtime baseline; G2:
> Order `AGENTS.md` by frequency of use: working rules first, infrastructure metadata last. Rules needed only in special cases (full artifact transaction details, artifact-only fallback and local-report template, product-specific modes such as a cloud chat) may live in scenario-defined support files, provided `AGENTS.md` keeps a short mandatory summary and an explicit pointer stating when to read them.

Попутно: в шаблоне строка `Project-memory language` встречается дважды (в `Infrastructure` и отдельной строкой) — в пилоте был дубль.

## F-31 (P2). Нет места для правил работы с конкретным пользователем

**Что произошло.** За месяц пользователь задал устойчивые правила: «отложенное не напоминать; молчание на вопрос — на потом», «ничего не удалять без согласия — в архив», «графы основной надписи пустые», «в корзины на сайтах не заходить», «не трогать файл, который я сейчас смотрю». Они были разбросаны по журналам и сводкам отдельных задач.

**Предложение.** Шаблон `AGENTS.md` (COMMON §11): обязательный раздел «Как работать с пользователем» (`Working with the user`) — правила, которые пользователь задал по ходу работы и которые действуют во всём проекте; пополняется в той же сессии, когда правило прозвучало. Сюда же — решение F-23 по отложенному: «не напоминать до запроса; вопрос без ответа = на потом, не да» (статус `parked` из F-23 остаётся полезным для задач целиком).

## F-32 (P2). Правила ведения документов (решение для F-24)

**Решение в пилоте.** Раздел `AGENTS.md` «Ведение документов»:
- рабочий документ в artifact root: сверху — одна строка «Редакция N, дата — главное изменение» и легенда; тело — текущее положение (устаревшее убирается); история — в конце, «История редакций», новые сверху; открытые вопросы — разделом, согласованным с «Открыто» задачи;
- запись `SOURCES.md` описывает источник (что, где, чем каноничен); ход работы в неё не дописывается (у части записей накопились датированные `Note:` — та же болезнь, что у `TASKS.md`);
- производные файлы (Excel, PDF, docx из скриптов) руками не правятся — меняется источник, файл перегенерируется;
- решения пользователя — с датой в «Решено», крупные — в `D-###`;
- стиль: язык проекта, единицы, пометка оценок, различие факт/решение/допущение.

Три документа макета (`03_…`, `04_…`, `07_…`) переведены на эту схему: шапки 5,0 / 4,6 / 1,4 тыс. знаков → 0,5 / 0,3 / 0,2.

**Предложение.** COMMON §9 / §11 `SOURCES.md` и новый подраздел «Working documents» с правилами выше.

## F-33 (P2). Знания «как работать» теряются при сжатии контекста

**Что произошло.** Приёмы, выясненные на ошибках (SolidWorks COM: размерный эскиз менять размерами, а не сдвигом точек; «Сохранить как» переключает открытую сборку; облегчённые компоненты; особенности сайтов поставщиков; ловушки командной строки), жили только в контексте чата и в сводках сжатия — каждое сжатие их сокращало.

**Решение в пилоте.** `tools/README.md`: перечень скриптов (что делает, как запускать, что нельзя запускать повторно) и раздел «Приёмы и подводные камни». Правило в «Ведение документов»: знание о работе записывается **в той же сессии**, когда выяснилось.

**Предложение.** COMMON §11 root-file guidance:
> When a project has scripts/tools, keep `tools/README.md` (or the scenario's equivalent): an index of tools with usage, plus a "pitfalls" section. Operational know-how discovered during work (tool quirks, failure modes, external-site specifics) is written there in the same session — chat context and compaction summaries are not durable.

## F-34 (P3). Словарь обозначений

**Что произошло.** Проверяющий агент не нашёл расшифровок СПИН, ЕП, КП/ТКП, «вставка ВАХ», обозначений деталей (A, Б/В, A2…), «режим А».

**Решение.** Раздел «Словарь» в `PROJECT.md`; ссылка на него из «Сейчас». COMMON §11 уже рекомендует `definitions/terminology` в `PROJECT.md` — предлагается сделать это обязательным для Standard-профиля и ссылаться на словарь из точки входа.

## F-35 (P2). Проверка «холодного старта» дочерней сессией — работает (решение для F-11)

**Как сделано.** Основной агент создал дочернюю задачу (функция приложения: отдельная сессия с самодостаточной инструкцией, без истории чата). Инструкция: начать как новый агент по `AGENTS.md`; ответить на 13 вопросов о решённом **без вопросов пользователю**, указывая, где найден ответ; проверить ссылки, противоречия, непонятные места; учесть объём чтения; **ничего не менять**, записать один отчёт в `_ai/research/`. Ожидаемые ответы основной агент сохранил у себя и в задачу не передавал — потом сверил: 13/13.

**Предложение.** COMMON §15:
> Prefer an independent fresh-agent run (e.g. a child/spawned session) with: a list of questions about settled decisions and current state; "answer only from project files, cite where found, write 'not found' rather than guess"; read-only except one report file; expected answers kept by the requesting agent and compared afterwards. Re-run after any restructuring of project memory. Treat contradictions between memory and working documents found by the run as findings to fix.

## F-36 (P3). Обновление стандарта и локальные отступления

**Что произошло.** `AGENTS.md` установлен из 0.8.6 и теперь существенно перестроен. Если обновление стандарта перезапишет файл целиком, перестройка пропадёт.

**Решение в пилоте.** Отступление записано в `_ai/infrastructure/MANIFEST.md` («Local deviation…: on a standard upgrade, do not overwrite `AGENTS.md` blindly — merge»).

**Предложение.** COMMON §8 (reapplication): обновление стандарта сливает изменения с установленным `AGENTS.md`, учитывая записанные в манифесте локальные отступления; перезапись целиком — только с явного согласия пользователя.

## Вне стандарта (эксплуатационные наблюдения)

- **Claude Code, приложение для рабочего стола.** Ссылки на файлы в ответах приложение открывает относительно папки, в которой открыта сессия, а не текущей подпапки; файлы вне папок сессии (например, `~/.claude/CLAUDE.md`) не открываются ни в панели, ни в Проводнике — это ограничение приложения. Правило вынесено в общий `CLAUDE.md` пользователя и продублировано в `AGENTS.md`.
- **Форк** наследует контекст на момент форка (включая тяжесть длинного чата); **дочерняя задача** стартует с самодостаточной инструкцией — легче, но работает только при хорошей памяти проекта.
- **Bash:** обратные кавычки (имена файлов в Markdown) внутри `python -c "…"` выполняются как команды — текст пропадает, а файл пытается запуститься; длинные правки — скриптом из файла (ср. F-14).
- **python-docx:** текст абзаца разбит на несколько run'ов — правка фрагмента должна идти по всему абзацу.

## Что сработало хорошо

- **Проверка дочерней сессией** дала объективную оценку («13/13 при 36 КБ») и 12 конкретных расхождений вместо общего ощущения «стало лучше».
- **Перенос дословно + построчная сверка.** Каждая перестройка (TASKS, STATE, AGENTS, документы) проверялась скриптом: каждая непустая строка старого текста есть в новом наборе файлов, кроме намеренно заменённых.
- **«Решено» как защита от переспрашивания** — простое правило, которое новый агент выполнил без дополнительных объяснений.
