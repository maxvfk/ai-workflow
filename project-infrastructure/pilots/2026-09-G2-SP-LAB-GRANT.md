## F-01 (P1). В G2 нет режима для агента с доступом только к control plane

**Что произошло.** Пользователь использует чат ChatGPT как резерв, когда исчерпаны лимиты основного агента. Такой чат видит GitHub и Google Drive, но не видит синхронизированную локальную папку.

**Недостаток стандарта.** В G2 описано одно отступление — artifact-only (есть папка, нет GitHub). Обратный случай — есть control plane, нет artifact root — не описан: где такой агент создаёт файлы, что он вправе менять в памяти проекта, как его работа сверяется.

**Как решено в пилоте.** Локальное расширение: чат читает память проекта и снимки ключевых документов; создаёт файлы только во входящей папке Google Drive; итог задачи — один новый отчёт в `_ai/inbox/`; остальную память проекта не изменяет; сверку выполняет агент с полным доступом; файлы во внешнем хранилище удаляет только пользователь.

**Рекомендация.** Добавить в G2 режим «только control plane», зеркальный artifact-only, с тремя элементами:

1. выбор режима по реально доступным операциям, как в G1, а не по названию продукта;
2. входящая зона для артефактов во внешнем хранилище — неканоническая до сверки;
3. отчёт о передаче работы в control plane (`_ai/inbox/`) — аналог `_LOCAL_AGENT_REPORT.md`, но в GitHub.

Для агентов, которые не находят `AGENTS.md` сами, — тонкий адаптер продукта.

**Реализация в пилоте описана отдельно:** [`2026-09-G2-control-plane-only-mode.md`](2026-09-G2-control-plane-only-mode.md) — текст раздела runtime, шаблон отчёта, устройство снимков, адаптер продукта и что показала первая проверка.

## F-02 (P1). Нет механизма снимков для агентов без доступа к artifact root

**Недостаток стандарта.** G2 запрещает дублировать артефакты в GitHub и копировать память проекта в artifact root, но не даёт легального способа показать ключевые **тексты** агенту, который видит только GitHub. При этом ценные рабочие документы часто текстовые: в пилоте это концепт разработки в md.

**Как решено в пилоте.** Каталог `_ai/snapshots/`: производные копии только для чтения, у каждой шапка с путём оригинала, датой и sha256; индекс с таблицей хэшей; обновляет только агент с полным доступом; состав определяет пользователь; снимки не регистрируются в `SOURCES.md` как источники.

**Рекомендация.** Ввести снимки как опциональный элемент G2. Контрольная сумма здесь уместна и не противоречит запрету G2 §11 на изменяемые хэши, поскольку снимок неизменяем по определению. Оговорить устаревание снимков и правило «работа ведётся только в оригинале».

## F-03 (P2). Синхронизатор возвращает старые версии — нет процедуры

**Что произошло.** Через десять часов после переноса папки в artifact root синхронизатор добавил пять файлов с суффиксом «(2)» и восстановил ранее замещённый файл. Все пять побайтово совпали с архивной редакцией, хранящейся в самой папке; текущие файлы не пострадали. Вероятная причина — другая машина со старым состоянием папки.

**Недостаток стандарта.** G2 §14 требует остановиться и не выбирать сторону, но не даёт критерия, когда каноническая версия устанавливается **доказательно**: например, побайтовое совпадение с зарегистрированной архивной версией при нетронутых текущих файлах.

**Рекомендация.** Добавить в §14 правило «доказуемый дубликат»: копия, побайтово совпадающая с зарегистрированной архивной или текущей версией, не блокирует работу, но фиксируется и удаляется только пользователем. В чек-лист переноса папок добавить проверку других машин, где лежала исходная папка.

## F-04 (P2). Каталог `PROJECTS.md` не обновляется при создании нового проекта

**Что произошло.** По границе активного проекта новый проект не может вписать себя в `PROJECTS.md`: каталогом владеет отдельный проект реестра. Строка появилась после ближайшего прохода обслуживания реестра — задержка была небольшой, но проект узнал об этом случайно, при очередном чтении каталога.

**Рекомендация.** Либо явное исключение: при bootstrap проект может **добавить** свою строку, не меняя чужие; либо механизм заявки (issue или файл-заявка в репозитории реестра), который подхватывает обслуживание.

## F-05 (P2). Ссылки между проектами внутри артефактов ломаются при переносе

**Что произошло.** В перенесённой папке концепта оказалось семь относительных ссылок вида `../Соседний_проект/...`. После переноса они не открываются: цель лежит вне workspace и не соответствует ни одному каталогизированному проекту.

**Недостаток стандарта.** COMMON §6 задаёт идентичность «Project ID + путь относительно канонического корня» для записей в `SOURCES.md`, но ничего не говорит о ссылках **внутри пользовательских документов** и о ресурсах, которые не входят ни в один каталогизированный проект.

**Рекомендация.** Соглашение для ссылок в артефактах: рядом с относительной ссылкой давать устойчивую текстовую, вида `[<ProjectID>] <путь>`; относительная остаётся подсказкой для текущей машины. Ввести статус «ресурс вне workspace» для материалов без Project ID.

## F-06 (P2). Artifact-only агенту некуда положить инструменты сборки

**Что произошло.** Локальный агент собирал docx из md конвертером и тремя скриптами постобработки. Скрипты остались в его облачной среде и пропадут вместе с ней. По G2 скрипты должны лежать в GitHub, а у artifact-only агента доступа к GitHub нет.

**Рекомендация.** Разрешить artifact-only агенту класть инструменты в явно названную папку artifact root с последующим переносом в GitHub при сверке; либо требовать, чтобы `_LOCAL_AGENT_REPORT.md` описывал воспроизводимый способ сборки.

## F-07 (P2). Временные рабочие папки приезжают вместе с переносимой папкой

**Что произошло.** В artifact root оказалась папка с рабочими файлами аудита, созданная, когда папка ещё лежала вне проекта. Требование G2 §15 (временная работа вне синхронизированной папки) нарушено не агентом, а самим фактом переноса.

**Рекомендация.** В процедуру сверки после добавления новой папки включить поиск временных рабочих каталогов; решение об их судьбе принимает пользователь.

## F-08 (P3). Отчёт artifact-only агента нужно выборочно проверять

**Что произошло.** `_LOCAL_AGENT_REPORT.md` оказался очень полезен, но в нём было указано четыре битых ссылки из семи фактических. Правило стандарта «отчёт не выше фактических артефактов» сработало: расхождение нашлось при сверке.

**Рекомендация.** Явно указать в процедуре сверки, что утверждения отчёта о количестве, составе и выполненных проверках перепроверяются выборочно по артефактам.

## F-09 (P3). Расходящиеся примеры формата Project ID

G2 §7 даёт пример `tokamak-cost-study` (строчные буквы через дефис), COMMON §6 — `TOK-COST`. В реальном workspace принят второй формат. **Рекомендация:** зафиксировать один рекомендуемый формат в COMMON и привести пример в G2 к нему.

## F-10 (P3). Не указан язык шаблона локального bootstrap `AGENTS.md`

Шаблон в G2 §7 написан по-английски, а язык памяти проекта по умолчанию `ru`. Неясно, переводить ли локальный bootstrap. В пилоте переведён, с сохранением английских ключей (`Project ID`, `Scenario`). **Рекомендация:** явно указать, что проза bootstrap-файла пишется на языке памяти проекта, а ключи остаются в английской форме.

## F-11 (P3). Cold-start без независимого агента

Проверка выполнена по цепочке «локальный `AGENTS.md` → GitHub API → память проекта → разрешение путей артефактов», без отдельного свежего агента: продуктовая политика не позволяет запускать субагентов без явного запроса пользователя. **Рекомендация:** дать в G2 проверяемый чек-лист cold-start, пригодный для такого случая, и различать в отчёте «проверено независимым агентом» и «проверено по чек-листу».

## F-12 (P3). Режим B требует настроенной git-идентичности

На машине не были заданы глобальные `user.name` и `user.email`; пришлось задать их локально в клоне. **Рекомендация:** упомянуть в G2 §4, что для небольших правок памяти проекта предпочтителен режим A, а режим B требует настроенной git-идентичности.

## F-13 (P2). Адаптеру продукта уровня workspace негде лежать

**Что произошло.** Для чата, общего для нескольких проектов, понадобился один текст инструкций со списком проектов (Project ID, репозиторий, входящая папка) и инструкция по адаптации остальных G2-проектов. Это уровень workspace, а не отдельного проекта. Профиль G2 / Project Registry хранит только `PROJECTS.md`, а родительские runtime-файлы в `PROJECTS/` запрещены — запрет правильный, но места для адаптеров уровня workspace не остаётся. Из активного проекта писать в репозиторий реестра нельзя.

**Как решено в пилоте.** Оба текста временно лежат в пилотном проекте.

**Рекомендация.** В профиле Project Registry разрешить репозиторию реестра хранить адаптеры продуктов уровня workspace и порождать список проектов из `PROJECTS.md`, чтобы не вести две таблицы. Инструкцию адаптации внести в стандарт как процедуру миграции, когда режим «только control plane» войдёт в G2.

## F-14 (P2). Обратные слэши искажаются при записи в репозиторий

**Что произошло.** В первом отчёте облачного чата формулы LaTeX пришли повреждёнными: `\(` и `\[` потеряли слэш, а `\rho` превратилось в управляющий символ CR и остаток `ho`. Та же ошибка повторилась у агента с полным доступом при записи через строковый литерал без raw-префикса.

**Рекомендация.** В шаблонах отчётов требовать формулы простым текстом с Unicode или в блоках кода. В процедуру сверки добавить проверку файлов на управляющие символы.

## F-15 (P3). Отчёт облачного чата нужно сверять с данными проекта

**Что произошло.** Облачный чат выполнил правила режима полностью: один новый файл во входящей папке, прочие файлы не изменены, отчёт по шаблону, статусы величин проставлены, предложения по памяти проекта отделены от выводов. Арифметика подтвердилась независимым пересчётом. Но исходные предпосылки обсуждения расходились с зафиксированными в проекте параметрами, и в отчёте это не отмечено: чат читал сводку требований, но опирался на контекст беседы.

**Рекомендация.** Добавить в шаблон отчёта раздел «расхождения с данными проекта»: агент обязан сверить предпосылки задачи с прочитанной памятью проекта и явно перечислить несовпадения. Считать сверку завершённой только после проверки предпосылок, а не одних расчётов.

## F-16 (P2). Инструкции внешнего проекта подгружаются средой

**Что произошло.** Агент читал исходные данные соседнего L1-проекта (только чтение). Среда автоматически подгрузила его `CLAUDE.md` и `AGENTS.md`, включая правила записи. Сначала это произошло при выполнении команды оболочки со сменой рабочего каталога; после введения правила «читать только по абсолютным путям» повторилось снова — при обычном чтении файла внутри чужого проекта, без смены каталога. Нарушения границы не было, но в контексте оказались две конкурирующие инструкции, и граница держалась только на внимательности агента.

**Вывод.** Предотвратить подгрузку чужих инструкций средствами агента в принципе нельзя.

**Рекомендация.** В COMMON §6 (workspace scope) закрепить не запрет, а приоритет: инструкции, подгруженные из внешнего проекта, **не действуют** для активной задачи и не отменяют правил активного проекта; при конфликте выигрывает активный проект. Правило должно жить в каноническом `AGENTS.md` каждого проекта многопроектного workspace.

## Что сработало хорошо

- **Разделение control plane и artifact plane.** Память проекта и её история — в GitHub, тяжёлые данные (около 18 тыс. файлов измерений) остались в синхронизированной папке без изменений. Ни разу не возникло соблазна перенести одно в другое.
- **Artifact-only режим и `_LOCAL_AGENT_REPORT.md`.** Локальный агент без доступа к GitHub выполнил работу и оставил передачу, пригодную для сверки. Формат отчёта оказался достаточным: по нему удалось восстановить решения автора и завести задачи.
- **Сверка по изменениям (COMMON §3).** Добавленные пользователем папки разбирались ограниченно, без полного сканирования проекта.
- **Правило «не выбирать сторону при конфликте» (G2 §14)** предотвратило работу со старой редакцией документа (F-03).
- **Bounded discovery при bootstrap.** Проект с 18 тыс. файлов инвентаризован без массового чтения; в `SOURCES.md` попали только значимые артефакты.

## Вне периметра стандарта

Одно эксплуатационное наблюдение записано в проекте, но стандарта не касается: в Claude Desktop под Windows после тихого автообновления приложение перезапускается и не переподключает существующие сессии к Remote Control, пока их не откроют локально.
