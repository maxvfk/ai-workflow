# Remote Control: диспетчер + сторож

Как держать сессии Claude Desktop (вкладка Code) доступными с телефона через claude.ai/code в мобильном браузере, даже после того как приложение само перезапустилось для обновления.

Решение принято 2026-10-22 по итогам разбора логов на компьютере RaiderMAX. Повторяется на каждом компьютере отдельно: у каждого компьютера свои диспетчер и сторож.

## Проблема

- Пока компьютер простаивает, Claude Desktop устанавливает скачанное обновление и перезапускается. В логе это `[stealth-update] Triggering stealth update after idle timeout`.
- При перезапуске процессы всех сессий останавливаются. После запуска сессии видны в окне, но не работают, поэтому Remote Control у них нет и с телефона их не видно.
- Remote Control сессии возвращается только тогда, когда сессия начинает отвечать, то есть когда в неё приходит сообщение. Если вызвать `set_remote_control` у остановленной сессии, получим отказ `Remote Control requires an active session. Send a message first.` Приложение запоминает запрос и выполняет его при следующем ответе сессии. Проверено 2026-10-22: служебное сообщение подняло сессию, и Remote Control включился через 2 секунды.
- Любая работающая сессия Code может включить Remote Control у другой сессии (`set_remote_control`) и отправить ей сообщение (`send_message`), а это сообщение запускает её процесс.

## Схема

- **Диспетчер** — отдельная сессия в пустой папке. Её единственная задача — быть на связи. С телефона ей пишут «подними сессию X», и она включает Remote Control у X и отправляет туда служебное сообщение.
- **Сторож** — задача по расписанию в Claude Desktop. Её запускает само приложение, поэтому перезапуск после обновления ей не мешает. Каждые 30 минут она проверяет диспетчера. Если у того выключен Remote Control, сторож включает его и отправляет служебное сообщение. Если всё в порядке, сторож ничего не пишет.

После обновления приложения диспетчер возвращается на телефон в течение одного интервала сторожа. Остальные сессии поднимаются через диспетчера по запросу.

## Модели

| Роль | Модель | Effort | Режим разрешений |
|---|---|---|---|
| Сторож | Claude Haiku 5.5 | low | Auto |
| Диспетчер | Claude Haiku 5.5 | low. Если путает похожие названия сессий — medium, если и тогда путает — Sonnet 5.5 с low | Auto |

Обе задачи сводятся к вызову 2–4 инструментов по готовой инструкции. Haiku 5.5 — самая дешёвая модель текущей линейки, по умолчанию у неё effort `medium`. Режим Auto нужен затем, чтобы диспетчер и сторож не ждали подтверждения на компьютере, за которым никого нет. Чтобы они не сделали ничего лишнего, ниже заданы запреты в настройках папки.

## Шаг 1. Папка диспетчера

Создайте папку `%USERPROFILE%\claude-hub`. Других файлов в ней быть не должно.

### `%USERPROFILE%\claude-hub\.claude\settings.json`

```json
{
  "permissions": {
    "deny": [
      "Bash",
      "PowerShell",
      "Edit",
      "Write",
      "NotebookEdit",
      "WebFetch",
      "WebSearch",
      "Agent",
      "mcp__scheduled-tasks",
      "mcp__ccd_session_mgmt__delete_session",
      "mcp__ccd_session_mgmt__archive_session",
      "mcp__ccd_session_mgmt__clear_session",
      "mcp__ccd_session_mgmt__stop_session",
      "mcp__ccd_session_mgmt__set_session_permission_mode",
      "mcp__ccd_settings__set_setting"
    ]
  }
}
```

### `%USERPROFILE%\claude-hub\CLAUDE.md`

```markdown
# Диспетчер Remote Control

Ты — служебная сессия-диспетчер. Твоя задача — быть на связи и по запросу поднимать другие сессии Claude Desktop, чтобы они стали доступны с телефона через Remote Control. Ничем другим не занимайся.

## Служебное сообщение
Если сообщение содержит «Служебная проверка», ответь одним словом «ок». Инструменты не вызывай.

## «Подними / активируй <описание сессии>»
1. Загрузи инструменты: ToolSearch с запросом
   `select:mcp__ccd_session_mgmt__list_sessions,mcp__ccd_session_mgmt__get_session,mcp__ccd_session_mgmt__set_remote_control,mcp__ccd_session_mgmt__send_message`
2. Вызови `list_sessions` (limit 30). Найди сессию по названию (`title`) или папке (`cwd`).
   - Если подходят несколько — перечисли кандидатов (название, папка, дата) и спроси, какую поднять.
   - Если ни одна не подходит — так и скажи. Не угадывай.
3. Вызови `set_remote_control` с `enabled: true` для найденного `sessionId`. Ошибку «requires an active session» игнорируй, это ожидаемо.
4. Вызови `send_message` для этой сессии с текстом:
   «Служебная проверка Remote Control. Ничего не делай, ответь одним словом «ок».»
5. Вызови `get_session` и ответь одной строкой: название сессии и `remoteControlState`.

## «Список»
Вызови `list_sessions` и выведи таблицу: название, папка, `remoteControlActive`, дата последней активности.

## «Твой id»
Вызови `get_session` с `"self"` и ответь его `sessionId`.

## Запрещено
- Отправлять другим сессиям любые сообщения, кроме служебного текста из пункта 4.
- Архивировать, удалять, останавливать и очищать сессии, менять их модель и режим разрешений.
- Читать и менять файлы, запускать команды, менять настройки приложения, создавать задачи по расписанию.
- Если просьба выходит за рамки этих правил, ответь, что диспетчер этого не делает.

Отвечай кратко, по-русски.
```

## Шаг 2. Сессия-диспетчер

1. Во вкладке Code создайте новую сессию в папке `claude-hub`. Модель Haiku 5.5, effort low, режим разрешений Auto.
2. Переименуйте её в «Диспетчер Remote Control».
3. Напишите в ней: `Твой id`. Сохраните полученный `sessionId` (вида `local_…`), он понадобится в шаге 3.
4. Включите Remote Control. Если включена настройка «Connect new sessions to Remote Control», он уже включён. Если нет — переключателем Remote Control на панели сессии.
5. Проверьте на телефоне: на claude.ai/code должна появиться сессия «Диспетчер Remote Control».

## Шаг 3. Сторож

Создайте задачу по расписанию: Code → Scheduled → New task. Можно и попросить любую сессию Code создать её инструментом `create_scheduled_task` с параметрами ниже.

- **Название:** `Сторож Remote Control`
- **taskId:** `rc-watchdog`
- **Расписание (cron, местное время):** `*/30 8-23 * * *` — каждые 30 минут с 8:00 до 23:30. Если нужно круглосуточно — `*/30 * * * *`.
- **Модель / effort:** Haiku 5.5 / low, если в настройках задачи есть выбор.
- **Режим разрешений:** Auto.
- **notifyOnCompletion:** false.
- **Промпт** (вместо `HUB_ID` подставьте `sessionId` из шага 2):

```text
Ты — сторож Remote Control. Выполни строго эти шаги и больше ничего не делай.

1. Загрузи инструменты: ToolSearch с запросом
   select:mcp__ccd_session_mgmt__get_session,mcp__ccd_session_mgmt__set_remote_control,mcp__ccd_session_mgmt__send_message
2. Вызови get_session с session_id = "HUB_ID".
   - Если сессия не найдена или isArchived = true — заверши ответом «диспетчер не найден или в архиве». Ничего больше не делай.
   - Если remoteControlState = "on" или "connecting" — заверши ответом «ок, подключено». Ничего больше не делай.
3. Иначе вызови set_remote_control с enabled = true и session_id = "HUB_ID". Ошибку «requires an active session» игнорируй.
4. Вызови send_message с session_id = "HUB_ID" и текстом:
   «Служебная проверка Remote Control от сторожа. Ответь одним словом «ок».»
5. Ещё раз вызови get_session для "HUB_ID" и заверши одной строкой с remoteControlState.

Запрещено: читать и менять файлы, запускать команды, писать в другие сессии, менять настройки, создавать или менять задачи.
```

## Шаг 4. Проверка

1. В диспетчере выключите переключатель Remote Control.
2. В Code → Scheduled запустите `rc-watchdog` вручную (Run now).
3. Ожидаемый результат: в диспетчере появилась служебная пара сообщений «Служебная проверка…» и «ок», Remote Control снова включён, на телефоне диспетчер виден.
4. Если сторож сообщает, что инструменты `ccd_session_mgmt` недоступны, значит в сессиях, запущенных по расписанию, их нет, и схема на этом компьютере не работает. Тогда остаётся запасной вариант (см. ниже).

## Как пользоваться с телефона

1. Откройте claude.ai/code в мобильном браузере, затем сессию «Диспетчер Remote Control».
2. Напишите `Подними сессию <название или папка>`, например `Подними сессию про занятия ФТТ`.
3. Через несколько секунд нужная сессия появится в списке сессий на claude.ai/code. Её первым сообщением будет служебная проверка — так и задумано.

## Расход и побочные эффекты

- Сторож — около 32 коротких запусков Haiku в сутки при расписании с 8 до 23, около 48 круглосуточно. Если диспетчер на связи, запуск сводится к одному `get_session`.
- Каждый запуск сторожа — это отдельная сессия в боковой панели. Если включена «Connect new sessions to Remote Control», такие сессии видны и на телефоне. Если это мешает, выключите эту настройку: диспетчеру Remote Control включается один раз и сохраняется, но новые рабочие сессии тогда придётся подключать вручную.
- Переписка диспетчера растёт только от запросов и от редких подъёмов. Если она стала длинной, создайте нового диспетчера и замените `HUB_ID` в задаче.

## Если не работает

- **Логи:** `%LOCALAPPDATA%\Claude\logs\main.log` (ищите `[remote-control] bridge_state`, `Enabling remote control`, `stealth-update`) и `remote-control.log`.
- **`bridge_state: "failed" ("auth")` / `Claude.ai login expired`:** истёк вход в claude.ai, Remote Control отваливается у всех сессий сразу. Помогает только заново войти в аккаунт в приложении. Сторож тут не поможет. Так было 2026-10-18.
- **Компьютер спит или выключен:** не работает ничего. Настройку «Keep computer awake while Claude works» стоит держать включённой, но спать между задачами компьютеру она не мешает.

## Рассмотренные и отклонённые варианты

- **Встроенный хостинг локальных сессий в Desktop (`rc-serve`)** решил бы задачу без сторожа: судя по логу, он «паркует» сессии при выходе и возобновляет их. Но на 2026-10-22 он выключен на стороне сервера (`state pending → off trigger=gate`) и в документации не описан. Если в настройках появится соответствующий переключатель, стоит проверить его.
- **Серверный режим терминальной версии `claude remote-control`** — отдельный процесс, обновления Desktop его не задевают. С телефона в нём можно открывать новые сессии в выбранной папке. Но существующие сессии Desktop он не поднимает. Подходит как запасной вариант: нужна установка Claude Code CLI и автозапуск через Планировщик заданий Windows.
- **Dispatch** работает только в мобильном приложении Claude, не в браузере. К тому же это ограниченная бета для части аккаунтов Pro/Max.
- **`/loop` и cron внутри сессии** умирают вместе с процессом сессии при перезапуске.
- **Облачные задачи по расписанию (routines)** не имеют доступа к Desktop на компьютере.
