# Памятка: выбор модели и режима для серьёзных задач

**Версия:** 2026-09-10  
**Назначение:** постоянные правила выбора; конкретные модели и benchmark-результаты перед важной задачей следует проверять заново.

## Исходные подписки

- **ChatGPT Plus**
- **Claude Pro (~$20/мес)**
- **Fable в Claude** — использовать только как крайнюю меру, когда ожидаемый выигрыш в качестве оправдывает расход credits/usage.

## Базовый принцип

Сначала определить **тип задачи и рабочую среду**, затем выбирать **вендора → модель → effort**.

Не выбирать модель только по общему рейтингу или одному benchmark.

## 1. Сначала выбрать среду

- **Обычный Chat** — постановка задачи, обсуждение методики, сложный локальный reasoning, подготовка промпта/Goal.
- **ChatGPT Work / Claude Cowork** — длинная автономная работа с файлами, web, инструментами и несколькими этапами.
- **Codex / Claude Code** — кодовые базы, terminal, git, тесты, автоматизация и инженерные workflow, где код является основной средой работы.

Если задача плохо сформулирована, сначала обсудить её в обычном чате на сильной модели, не расходуя дорогой agentic allowance.

## 2. Оценить профиль задачи

Перед выбором модели оценить:

1. **Reasoning depth** — насколько сложны отдельные выводы.
2. **Agentic horizon** — сколько взаимозависимых шагов потребуется.
3. **Autonomy** — насколько агенту придётся самому выбирать дальнейший путь.
4. **Context heterogeneity** — сколько типов данных и источников нужно объединить.
5. **Verification burden** — насколько важны cross-checking, независимые пересчёты и проверка источников.
6. **Error cost** — насколько дорого обойдётся незамеченная ошибка.
7. **Tool fit** — где находятся данные и какой продукт удобнее с ними работает.
8. **Usage economics** — ожидаемое качество относительно лимитов и credits.

## 3. Как выбирать effort

- **Low** — алгоритм в основном понятен; reasoning нужен, но сложных развилок мало.
- **Medium** — default для серьёзной автономной работы: много анализа и промежуточных решений, но не каждый шаг экстремально сложен.
- **High** — когда основная сложность именно в трудных рассуждениях, неоднозначных физических/математических выводах, сложном debugging или дорогих ошибках.

Важно: высокий effort не означает автоматически лучший результат. Для длинного Work/Cowork лучше выбрать подходящий effort **до запуска** и без необходимости не менять его в середине большой сессии.

## 4. Как выбирать между ChatGPT и Claude

Смотреть не на бренд, а на соответствие конкретной задаче:

- long-horizon agentic work;
- research и source verification;
- scientific/engineering reasoning;
- coding;
- long-context synthesis;
- tool use / computer use;
- factuality и hallucination rate;
- steering stability;
- стоимость по allowance/credits.

Для важной задачи сравнивать обе экосистемы и выбирать лучший **workflow целиком**, а не только модель.

## 5. Как учитывать benchmarks

Benchmarks — обязательный, но не единственный источник данных.

Приоритет:

1. **релевантные независимые benchmarks**;
2. **реальные task-oriented / long-horizon evals**;
3. **свежие прямые A/B comparisons**;
4. **официальные vendor benchmarks**;
5. **community reports** как дополнительный практический сигнал.

Нельзя переносить лидерство в одном benchmark на все задачи.

Примеры:
- SWE-bench → полезен для coding, но слабый аргумент для научного аудита;
- math benchmark → полезен для формального reasoning, но почти ничего не говорит о browser/tool workflow;
- long-context recall ≠ качественный synthesis;
- хороший browser benchmark ≠ низкий hallucination rate.

Перед важной задачей учитывать **свежие** результаты, потому что относительное положение моделей быстро меняется.

## 6. Практическое правило выбора

Когда задача неочевидна, сформулировать её в обычном ChatGPT-чате и спросить:

> Подбери оптимальный режим для этой задачи с учётом ChatGPT Plus и Claude Pro.  
> Сравни подходящие Chat / Work / Cowork / Code-варианты, модель и effort.  
> Учитывай свежие релевантные benchmarks, качество результата и расход лимитов.  
> Fable рассматривай только как крайнюю меру.

Желаемый формат ответа:

- **Основной выбор**
- **Лучшее качество / usage**
- **Максимум качества**
- **Почему не основные альтернативы**
- **Какие benchmarks действительно релевантны**
- **Нужно ли делать независимую проверку второй моделью**

## 7. Для особо важных научно-инженерных задач

Полезный шаблон:

**модель A** → основная работа  
**модель B другого вендора** → adversarial review / независимая критика

Это часто полезнее, чем просто увеличивать effort у той же модели.

## Короткое правило

**Сначала workflow, затем модель, затем effort.  
Benchmarks учитывать по релевантности задаче, а не по общему месту в рейтинге.  
Для длинной работы выбирать effort заранее.  
Два вендора использовать не только как альтернативы, но и для независимой проверки.**
